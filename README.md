# Baby Tracker

Дневник малыша: сон, кормления, подгузники, вес и рост, события «впервые» и напоминания.

Приложение работает без сервера: данные хранятся в браузере (IndexedDB). Устанавливается на
телефон как приложение (PWA) и открывается без интернета.

## Статус

- **Этап 1 (готов): основа.** База данных, логика времени и итогов дня,
  расписание напоминаний с движком уведомлений, резервная копия, профиль ребёнка, экран
  первого включения, настройки (дети и тема), каркас приложения с навигацией и PWA.
- **Этап 2 (готов): экраны MVP.** «Сегодня» с итогами-карточками и разделами (сон, кормления,
  подгузники), история по дням с таблицей недели, рост с графиком, события «впервые» с фото,
  напоминания (все типы правил, «Сделано», перенос), резервная копия в настройках. Заглушек
  не осталось.
- **Будущее:** Node.js-сервер — вход по email, синхронизация, приглашения второму родителю,
  напоминания при закрытом приложении (Telegram-бот, затем веб-пуш). Возможная полировка:
  ВОЗ-перцентили на графике роста, фильтры в истории.

## Публикация

Каждый пуш в `main` собирается и публикуется в GitHub Pages workflow
`.github/workflows/deploy.yml`: https://cyrexn8.github.io/baby-tracker/

- Включить один раз: Settings → Pages → Source → GitHub Actions.
- Адрес задаёт переменная `BASE_PATH` в workflow (`/baby-tracker`); локально приложение
  живёт в корне — base, манифест PWA и роутер подстраиваются автоматически (`vite.config.ts`).
- GitHub Pages не умеет SPA-fallback, поэтому workflow добавляет в сборку `404.html`
  (`scripts/generate-404.mjs`): прямой заход по адресу страницы возвращает пользователя
  в приложение.

## Правила проекта

- **Данные — только через репозитории** из `src/lib/repositories`. Компоненты не обращаются
  к `db` из `src/lib/db/db.ts` напрямую. Репозиторий детей называется `childProfiles`
  (таблица в базе — `children`), чтобы не путать его с `children` из React.
- **Реактивность — через `useLive`** (`src/lib/hooks/useLive.ts`) или готовые хуки в
  `src/features/<раздел>/hooks.ts`. Пока `loading` равно `true`, данных ещё нет.
- **Живой запрос замечает только записи через Dexie.** Запись, положенная в IndexedDB
  «в обход» (сырым API), появится в приложении лишь после перезагрузки. В тестах кладите
  данные через репозитории.
- **Записи удаляются мягко**: `remove()` ставит `deletedAt`. Это нужно для будущей синхронизации.
- **«День малыша» начинается в 6:00** (`DEFAULT_DAY_START_HOUR`). Ночной сон через полночь
  относится к дню начала. Отбор записей за день — через `listForDay`, а не через полночь.
- **Ничего не менять без необходимости** в `vite.config.ts`, `tsconfig*.json`, `src/lib/db/`,
  `src/lib/repositories/`, `src/lib/time/`, `src/lib/reminders/`, `src/lib/backup/`:
  на этой логике написаны тесты, и её не планируется переделывать.
- **Текст интерфейса — на русском**, сообщения об ошибках — понятные пользователю.
- **Тапы не мельче 44 px**: дневник заполняют одной рукой, часто ночью.
- **Формы**: `react-hook-form` + `zod` (`zodResolver`), поля оборачиваются в `Field`,
  которое связывает подпись, подсказку и ошибку для скринридеров.
- **Подтверждение необратимого** — через `ConfirmDialog`; обратная связь — `toast` из `sonner`.
- **Форма в панели рендерится, только пока панель открыта**: `{open && <Форма />}` внутри `Sheet`.
  Иначе значения «по умолчанию сейчас» берутся на момент загрузки страницы, а закрытая панель
  держит скрытые поля в разметке. Образец — `DiaperFormSheet`.
- **Брать готовое, прежде чем писать своё** (`src/components/ui/`):
  `Badge` — счётчик по разделу (`tone="diaper"`), `SkeletonList` — загрузка списка,
  `DateTimeField` — поле даты и времени (`optional` — пометка «необязательно»),
  `RunningTimerCard` — панель идущего таймера (значок, часы, кнопки; `busy` блокирует кнопки),
  `Button size="xl"` — кнопка 64 px, `SegmentedControl` — переключатель вариантов.
- **Помощники**: `undoableCreateToast(message, undo)` из `src/lib/toast.ts` — сообщение
  «Записано: …» с кнопкой «Отменить»; `isForgottenTimer` из `src/lib/time/timer.ts` —
  правило забытого таймера.
- **Правило забытого таймера** — `src/lib/time/timer.ts`: таймер сна или кормления дольше
  12 часов по кнопке завершения не сохраняется молча — открывается форма изменения
  с концом «сейчас». Проверка — `isForgottenTimer(startAt, now)`.
- **Идущий таймер живёт в базе** (`endAt === null`), а не в состоянии компонента:
  прошедшее время всегда считается от `startAt`, перезагрузка его не сбрасывает.
- **Соседним разделам нельзя давать одинаковый `key`** (ошибка React о дублирующихся ключах).
  Чтобы при смене ребёнка разделы сбросились, ключ ставят на общую обёртку
  (см. `src/features/today/TodayPage.tsx`).
- **Новые зависимости не добавлять** без необходимости: всё нужное уже стоит
  (в том числе `recharts` для графиков этапа 2).

## Напоминания

Логика готова и покрыта тестами, интерфейс — на этапе 2:

- `src/lib/reminders/schedule.ts` — когда следующее наступление по правилу
  (разово, каждый день, по дням недели, по интервалу);
- `src/lib/reminders/state.ts` — состояния `upcoming` / `due` / `overdue` / `snoozed` / `done`
  и сортировка для списка;
- `src/lib/reminders/actions.ts` — «сделано», «отменить сделано», «напомнить позже»;
- `src/lib/reminders/ReminderProvider.tsx` — считает состояния каждые 30 секунд и показывает
  уведомление в момент наступления. Метка с числом ждущих напоминаний — `useDueRemindersCount()`;
- удобный вход для экрана — `src/features/reminders/hooks.ts`.

Пока приложение работает без сервера, напоминание приходит, только если приложение открыто.
Разрешение на уведомления нужно спрашивать в момент, когда пользователь создаёт первое
напоминание (`requestNotificationPermission` из `src/lib/notifications/notifications.ts`).

## Обновление приложения

Приложение — PWA: service worker (`src/sw.ts`) кэширует сборку, и оно открывается без интернета
на любом адресе. При выходе новой версии страница **не** перезагружается сама — иначе
сбросилось бы начатое заполнение записи. Пользователю показывается сообщение с кнопкой
«Обновить» (`src/main.tsx`). Не возвращайте `registerType: 'autoUpdate'`.

## Тесты

`npm test` — Vitest + Testing Library, база — на `fake-indexeddb`.

- Логика времени и итогов дня: `src/lib/time/*.test.ts` (включая перевод часов).
- Расписание и состояния напоминаний, движок уведомлений: `src/lib/reminders/*.test.ts(x)`.
- Репозитории и настройки: `src/lib/repositories/repositories.test.ts`.
- Резервная копия: `src/lib/backup/backup.test.ts`.
- Форма ребёнка: `src/features/child/ChildForm.test.tsx`.

В тестах с базой вызывайте `clearDatabase()` из `src/test/helpers.ts` в `beforeEach`.
Помощники `at(год, месяц, день, часы, минуты)` там же строят локальную дату.

## Что учесть в зависимостях

Версии свежие, и в них есть отличия от того, что часто встречается в примерах:

- **React Router 8**: пакет `react-router-dom` удалён. `RouterProvider` импортируется из
  `react-router/dom`, остальное (`Link`, `NavLink`, `useNavigate`, `Outlet`, …) — из `react-router`.
- **lucide-react 1.x**: часть старых имён убрана. `Home` → `House`, `Trash2` → `Trash`,
  `AlertCircle` / `AlertTriangle` отсутствуют. Если иконки нет, проверьте имя по ошибке типов.
- **TypeScript 7**: `erasableSyntaxOnly` — без `enum`, пространств имён и параметров-свойств.
- **Tailwind CSS 4**: без `tailwind.config.js`. Цвета приложения объявлены в `src/index.css`
  (`@theme`): `bg-surface`, `text-fg`, `text-fg-muted`, `bg-primary-soft`, `text-accent`,
  `text-danger`, а цвета разделов — `bg-cat-sleep-soft`, `text-cat-sleep-strong` и так далее.
- **Линтер — oxlint**, не ESLint: typescript-eslint пока не поддерживает TypeScript 7.
- **Dexie 4.4**: тип таблицы — `Table<T, string>`. `EntityTable<T, …>` здесь не подходит:
  его второй параметр — имя ключевого поля, а записи мы сохраняем с готовым `id`.
- **zod 4**: русские сообщения включены в `src/lib/validation/setup.ts`. Схемы записей
  помечены `: z.ZodType<…>` — так они не разойдутся с типами из `src/lib/db/schema.ts`.

## Подводные камни автоматических проверок в браузере

- Закрытые панели остаются в разметке (форм — только если форма не убрана по правилу выше).
  Ищите элементы внутри `dialog[open]` или уточняйте селектор (`main button.h-16`),
  иначе запрос найдёт кнопку и в закрытой панели.
- На странице два `<header>`: шапка приложения и заголовок страницы (`PageHeader`).
- В поле даты обычный `fill('2026-05-12')` работает как есть: Playwright сам ставит значение
  и вызывает события, форма его видит.

## Ограничения текущей версии

- Данные живут только в браузере на одном устройстве. Очистка данных сайта их удалит —
  делайте резервную копию (`buildBackup` / `importBackup` в `src/lib/backup/backup.ts`).
- Входа и общего доступа второму родителю пока нет.
- Напоминания приходят, только пока приложение открыто. При закрытом — после появления сервера.
